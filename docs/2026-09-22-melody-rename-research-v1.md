# Melody rename — research map

Dated 2026-09-22. Question as asked: "rename and rebrand everything to be Melody"; depth picked
"Brand + app identity" (visible brand, Melody.app, its app ID and data folders, with a one-time
migration of `~/Library/Application Support/Goose` and `~/.config/goose`). Internals stay goose:
crate names, the `goose` binary, `GOOSE_*` env vars, Rust identifiers.

## The surprise (lead finding)

**The backend's folders are not the app's: `~/.config/goose`, `~/.local/share/goose`,
`~/.local/state/goose` belong to the `goose` binary, which the CLI shares, and are named in three
Rust strategies plus nine hard-codes.** Moving them splits the desktop from the CLI (sessions,
recipes, OAuth caches) and breaks every routine, since `schedule.json` stores absolute paths into
`~/.local/share/goose/scheduled_recipes/` (14 on this machine). The app's own folder,
`~/Library/Application Support/Goose`, is one switch (`productName`) and one hook (`main.ts:190-197`).

Second surprise, outside the rename: **the auto-updater is on and targets upstream.**
`updates.ts:1` `UPDATES_ENABLED = true`; `utils/autoUpdater.ts:343-351` feeds from
`aaif-goose/goose`; `utils/githubUpdater.ts:458-460` looks for `Goose.zip`. A packaged fork build
can be offered upstream's release and swap it in over itself (`githubUpdater.ts:88,229-240`).

## Reframe trail

1. Rename strings and folders > strings are mechanical, folders are two different owners > which
   folders are the app's?
2. Move `~/.config/goose` too > shared with the CLI, 3 strategy copies, absolute paths in
   `schedule.json`, keychain service `"goose"` > is a backend folder move worth its risk?
3. Change the bundle > `productName` also silently changes the bundle ID and the app menu match >
   pin the ID, fix the match.

## Recorded decisions

- `DESIGN.md` §Iconography (2026-09-22) — the product name and `Goose.app` "were left as they are"
  when the emblem changed; this rename reopens that by the user's word.
- `forge.config.ts:125` — flatpak id kept "for backwards compat"; Linux packaging is out of use here.

## Options → pick

| Option | Owns | Trades away |
|---|---|---|
| A. App folder only | Melody.app, a pinned bundle ID, `Application Support/Melody` migrated once; backend folders stay `goose`, shared with the CLI | `~/.config/goose` keeps its name |
| B. App folder + backend folders | Every folder says melody | CLI split, 3 Rust strategies + 9 hard-codes, `schedule.json` rewrite, spine edits in `crates/goose` |

Pick: A — confirmed by the user 2026-09-22 ("App folder only", "Turn it off", "Keep goose://",
and, against the recommendation to leave them, "Yes, edit the prompts" for the self-name)
- Backend folders are internals by the depth rule: `goose serve` owns them, like the binary.
- Keep `goose://` (links in the wild, generated by the backend) and keychain service `"goose"`.
- Pin `appBundleId` to `com.melody.app`-style; macOS permissions are asked once more.
- Turn the updater off in the same change: a fork build with no releases of its own.

## Scope — in / out / protected

- in: `package.json`, `forge.config.ts`, `forge.{deb,rpm}.desktop`, `index.html`,
  `manifest.webmanifest`, `main.ts` (migration, names, menu match, zh-CN keys),
  `utils/autoUpdater.ts`, `updates.ts`, `vite.main.config.mts`, `justfile`, the 60 brand + 2 mixed
  i18n messages and their source `defaultMessage`s, 16 locales, the hard-coded renderer strings,
  the brand tests, `DESIGN.md` vocabulary, the backend's four desktop-visible strings, the self-name in the backend
  system prompts (`prompts/system.md`, `subagent_system.md`, `tiny_model_system.md`,
  `prompt_manager.rs:144`, `live_voice/service.rs:29`, the local-inference copies).
- out: crate, binary, env var, `.goosehints`, `goose://`, keychain service, backend folders (depth
  rule); upstream `documentation/` and workflows (upstream's site); `persist:goose` partition name.
- protected: `~/Library/Application Support/Goose` is copied, never moved or deleted, until the
  user confirms Melody reads it; the walk profile (`GOOSE_USER_DATA`) skips the migration.
